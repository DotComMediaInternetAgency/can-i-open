# Repository Metadata and Discoverability

Keep the GitHub repository page accurate, easy to understand, and discoverable by people looking for a native macOS utility to inspect or change file associations.

## About description

The current repository description is:

> A native macOS app for inspecting and managing file type defaults in bulk.

Keep the About description to one concise, factual sentence that names the platform, the core task, and the bulk workflow. Update it when the product's purpose materially changes. Avoid claims about features the app does not provide, repeated keyword lists, and promotional superlatives.

## Topics

Use a small set of relevant GitHub repository topics to classify the project. The current topics are:

- `macos`
- `swift`
- `file-associations`
- `default-apps`
- `launchservices`
- `file-types`
- `macos-utility`

Topics should accurately describe the platform, implementation language, or central user problem. Add or remove a topic when the project scope changes; do not add unrelated popular topics or near-duplicate terms for keyword stuffing. GitHub permits up to 20 topics, but this project intentionally uses only the focused set above. GitHub topic names are public, including for private repositories.

## README wording

- Describe capabilities in normal user-facing language. Relevant phrases include “macOS file associations,” “default apps,” and “file types.” Use them where they clarify the product rather than repeating them mechanically.
- Keep screenshots, release links, platform requirements, and limitations current.
- Keep the README, GitHub About description, topics, and shipped behavior consistent.
- Do not promise search rankings or imply that metadata alone guarantees visibility in GitHub or external search engines.

## Review checklist

When the repository's audience or purpose changes, review:

1. GitHub About description and homepage URL.
2. Repository topics for accuracy and relevance.
3. README title, summary, feature list, screenshots, and release link.
4. Credits and license notices for the original project and this fork.

GitHub's current topic limits and editing steps are documented in [Classifying your repository with topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).
